# 慧学通（Huixuetong）系统实测痛难点与完善方案

> 版本基线：`0.0.1-SNAPSHOT`（2026-11-08 工作区）
> 阅读范围：`src/main/java` 全部 **151 个 Java 文件 / 8788 行**逐文件通读；`resources` 全量（含 7 个 Prompt 模板、`application.yml`、`schema-extend.sql`）；前端 19 个页面按路由、接口层与关键交互通读；实库 **22 张表**核对；本机启动后实测登录 / AI 同步 / SSE / 知识库上传 / 分页 / 统计 / 权限。
> 结论口径：只写“能复现、有证据”的问题；每条都给出证据、根因、影响和对应改法。

## 0. 先回答：上一轮“失败”的原因

上一轮不是项目整体跑不起来，而是 **构建环境 + 数据库方言 + 局部功能未接线** 三类问题叠加。按发生顺序：

| # | 失败现象 | 直接原因 | 证据 | 现状 |
|---|----------|----------|------|------|
| 0.1 | `mvn spring-boot:run` 直接退出，`[exit code: 1]` | Maven 要写工作区外的本地仓库，被文件沙箱拒绝：`AccessDeniedException: C:\Users\mq\.m2\repository\org\springframework\boot\resolver-status.properties` | 后台任务输出 + `.tmp_app.log` | 已用一次完整权限执行 `mvn -o compile` 通过；`spring-boot:run` 12.3s 正常启动（Redis 8.8.0 自动拉起） |
| 0.2 | 知识库上传 500 | 代码用 `CAST(? AS JSON)`，而本机是 **MySQL 5.5.40**，5.5 没有 JSON 类型 | 实测返回 `SQLSyntaxErrorException ... near 'JSON), NOW())'` | 未修，见 T2 |
| 0.3 | AI 回答后操作日志写入失败 | `emp_log.return_value` 是 `utf8`，回答里的 emoji（😊）触发 `Incorrect string value ... error code 1366` | 日志实测堆栈 | 未修，见 T8 |
| 0.4 | 考勤“新增”按钮报“系统繁忙” | 前端有 `POST/PUT/DELETE /attendance`，后端 `AttendanceController` **没有写接口**，`HttpRequestMethodNotSupportedException` 被兜底成 500 | `POST /attendance` 实测 500，日志 `Request method 'POST' is not supported` | 未修，见 T3 |
| 0.5 | `mvn test` 失败 | 101 个测试中 2 个失败：`DeptControllerTest.add_emptyName`（期望 500，实际 400）、`SecureSqlExecutorTest.testExecuteValidQuery`（期望 false，实际 true） | surefire 输出 | 未修，见 T13 |

**一句话**：环境问题是“Maven 仓库不在工作区”，运行期问题是“MySQL 5.5 方言 + 部分功能只写了一半”。项目本身能启动、AI 主链路能通。

## 1. 系统实况：代码里到底有什么

### 1.1 规模与结构

| 维度 | 实况 |
|------|------|
| 后端 | 151 个 Java 文件 / 8788 行；18 个 Controller、22 个 Mapper、6 个域 Tool 类（39 个可用 `@Tool`） |
| 前端 | 19 个页面 + 16 个 API 模块；Vue3 + Vite + Element Plus + ECharts |
| 数据库 | 22 张表；MySQL **5.5.40**；无 Flyway、无业务表 DDL 入库 |
| AI | Spring AI 1.0.0-M6；OpenAI 兼容协议；注册表里只有 `deepseek`、`mimo` 两个模型 |
| 测试 | 101 个用例（2 失败 / 2 跳过），以单测为主 |

### 1.2 真实调用链路（与 README 的差异）

```
前端 fetch('/api/ai/chat')
  → TokenInterceptor（只校验 JWT 是否有效，不校验角色）
  → RateLimitInterceptor（全局 Guava RateLimiter，10 QPS）
  → AiChatController（SseEmitter 120s）
  → AiOrchestratorService
      ├─ SafeGuardAdvisor（正则）
      ├─ IntentRouter（纯规则；"多少/查询/流程/写"等关键词）
      ├─ RedisChatHistoryManager（40 条，24h）
      ├─ QuestionAnswerAdvisor（旧版：只查 notice type=3 做关键词匹配）
      ├─ AiPromptBuilder（角色/数据字典/工具目录/安全规则）
      ├─ 按 Intent 注入 Tool → Spring AI Function Calling
      └─ 异步落库 hxt_ai_chat_record + token 估算
```

关键差异：**编排层用的是旧的 `QuestionAnswerAdvisor`，不是新写的 `KnowledgeRagAdvisor` / `KnowledgeBaseService`**。所以“知识库上传”与“AI 回答”目前是两条互不相交的链路。

### 1.3 实库数据（决定演示效果）

| 表 | 行数 | 备注 |
|----|------|------|
| emp / student / clazz | 31 / 18 / 7 | 只有员工账号，学生无账号 |
| course / course_schedule | 16 / 21 | 排课只有 Mapper 和 Tool，无 Controller、无页面 |
| attendance / score / exam | 54 / 31 / 12 | 考勤 21 条 `clazz_id` 指向不存在的班级 |
| payment / employment / violation_log / notice | 30 / 16 / 16 / 11 | 缴费只有记录，无在线支付 |
| hxt_ai_chat_record | 125 | 有历史对话 |
| hxt_token_usage | 757 | Token 为字符数估算 |
| hxt_ai_trace / hxt_tool_call_log | **0 / 23** | 追踪表从未写入；工具日志仅历史遗留 |
| hxt_knowledge_doc / chunk | **0 / 0** | 上传必失败，所以始终为空 |
| emp_log | 299 | emoji 回答会写失败 |

## 3. 痛难点清单（按“会不会挡住答辩”排序）

### P0 阻断级（不修就没法讲）

#### P0-1 知识库上传 100% 失败，RAG 是“假 RAG”

- **现象**：任意文件上传 `/knowledge/upload` 都返回 500，`hxt_knowledge_doc` 永远 0 行。
- **证据**：`CAST(? AS JSON)` 在 MySQL 5.5 报语法错误；`KnowledgeChunkMapper.insert` 第 604 行。
- **第二层问题**：即使上传成功，`AiOrchestratorService` 注入的是 `QuestionAnswerAdvisor`（只查 `notice type=3` 做 `contains` 匹配），`KnowledgeRagAdvisor` 从未被调用。
- **影响**：论文里“RAG 检索增强、混合检索、引用来源”全部无法演示；问“缓考流程”时模型只能瞎编或说“暂无”。
- **改法**：T2。

#### P0-2 考勤新增/编辑/删除全部 405

- **现象**：页面有“+ 新增考勤”“编辑”“删除”，点击报“系统繁忙”。
- **证据**：`AttendanceController` 只有 4 个 GET；`POST /attendance` → `HttpRequestMethodNotSupportedException` → 全局兜底 500。
- **影响**：教师端“考勤管理”只能看不能录，业务闭环断掉；开题报告里的“考勤异常→预警”也失去数据入口。
- **改法**：T3。

#### P0-3 只有“管理员”一种角色，学生端整体缺失

- **现象**：登录成功即 `role=ADMIN`；所有员工看到同一套菜单；`student` 表没有账号/密码。
- **证据**：`EmpServiceImpl.login` 固定 `claims.put("role","ADMIN")`；`TokenInterceptor` 只解析不鉴权；`PermissionAspect` 只判断“是否登录”。
- **影响**：开题报告的“教师/学生/管理员三类角色”无法成立；学生端 6 个功能全部落空；数据权限（教师只看自己班、学生只看自己）无法实现。
- **改法**：T5 + T6 + T10。

#### P0-4 密码明文存储与比对

- **现象**：数据库里 `123456 / 654321` 直接可读；登录用 `dbEmp.getPassword().equals(emp.getPassword())`。
- **证据**：`SELECT username,password FROM emp` 实测；`EmpServiceImpl` 第 1052 行。
- **影响**：安全章节无法自圆其说；答辩老师一眼能看出；也无法做“密码重置/首登改密”。
- **改法**：T5（BCrypt + 兼容迁移）。

#### P0-5 Actuator 未鉴权，`/actuator/env` 公网可读

- **现象**：不带 token 访问 `/actuator/env` 返回 200。
- **证据**：`WebConfig` 与 `TokenInterceptor` 都放行 `/actuator/**`；`application.yml` 暴露 `health,info,metrics,env,loggers`。
- **影响**：环境变量、配置项可被枚举；与“安全审计”叙事冲突。
- **改法**：T6（收敛端点 + 鉴权）。

### P1 严重（不修会被追问细节）

#### P1-1 工具调用标记泄漏到回答里

- **现象**：问“缓考申请流程是什么”，接口直接返回：
  ```
  <｜｜DSML｜｜ calls>
  <｜｜DSML｜｜ invoke name="searchNotice">
  <｜｜DSML｜｜ parameter name="keyword" string="true">缓考</｜｜DSML｜｜ parameter>
  ...
  ```
- **证据**：`/ai/chat/sync` 实测原文；前端只过滤 `[[TOOL]]` 和 `<longcat_tool_call>`，不认 DSML。
- **根因**：`deepseek-v4-flash` 走的是自家工具调用编码，Spring AI M6 的 OpenAI 解析器没识别，文本被当成正文透传。
- **影响**：用户看到“乱码”；同一问题换模型结果不同；演示事故高发。
- **改法**：T4（后端统一清洗 + 选型验证）。

#### P1-2 日期幻觉与数据口径错误

- **现象**：问“今天有多少学员考勤异常”，回答写成“**2026-07-04（今日）** 考勤统计”，而系统当天是 11-08，且当天无考勤数据。
- **证据**：SSE 实测；`attendance` 最新日期为 07-04。
- **根因**：System Prompt 没有注入“当前日期”；工具默认参数是 `LocalDate.now()`，模型却拿最近有数据的日期当“今天”。
- **影响**：统计类回答不可信；论文的“数据即问即查”会被质疑准确性。
- **改法**：T4（Prompt 注入日期 + 工具返回显式日期 + 空结果提示）。

#### P1-3 分页在内存里做（成绩/缴费/公告/违纪/就业）

- **现象**：这些接口先 `findAll()` 全表加载，再 `stream().filter()`、`subList()` 分页。
- **证据**：`ScoreController.page`、`PaymentController.page`、`NoticeController.page`、`ViolationController.page`、`EmploymentController.page`。
- **影响**：数据量上万后 P95 明显上升、内存压力大；总数与分页在并发下可能不一致；论文“性能测试”章节很难看。
- **改法**：T7（SQL `LIMIT/COUNT` 下沉）。

#### P1-4 没有外键，39% 的考勤是孤儿数据

- **现象**：`attendance` 54 行里 **21 行** `clazz_id` 指向不存在的班级（如 `clazz_id=2`），列表里 `clazzName` 为 `null`。
- **证据**：`LEFT JOIN clazz ... WHERE c.id IS NULL` 统计 21；接口返回 `clazzName:null`。
- **影响**：按班级统计/预警会漏数据；演示时出现“有考勤、没班级”。
- **改法**：T1（清洗 + 外键/校验）。

#### P1-5 字符集导致审计日志丢写

- **现象**：AI 回答含 emoji 时 `emp_log` 插入失败，`LogAspect` 只打错误日志，操作审计静默丢失。
- **证据**：`emp_log.return_value` 为 `utf8`，`hxt_ai_chat_record.ai_answer` 为 `utf8mb4`；实测 1366。
- **影响**：日志页缺记录；审计链断裂。
- **改法**：T8（列改 `utf8mb4` + 安全截断）。

#### P1-6 默认模型 `longcat` 漂移

- **现象**：`ChatClientConfig` 默认 `longcat`，`AiChatRequest.modelType` 默认 `longcat`，`ScheduledAgentService`、`MemorySummarizer` 硬编码 `longcat`；但注册表里只有 `deepseek/mimo`。
- **证据**：`config/models.json` 实测；`/ai/models` 只返回 2 个。
- **影响**：不传 modelType 时先抛异常再降级；定时周报/摘要必失败；日志噪音。
- **改法**：T4（默认取注册表第一个 + 去掉硬编码）。

#### P1-7 刷新后历史对话永远为空

- **现象**：AI 页刷新后不恢复历史。
- **证据**：后端 `Result.success` 的 `code=1`，前端判断 `result.code === 200`（`views/ai/index.vue` 第 125 行）。
- **影响**：多轮体验断档；演示“上下文消歧”时容易翻车。
- **改法**：T4（前端统一按 `code === 1`）。

#### P1-8 大量“写好但没接线”的代码

| 组件 | 现状 | 证据 |
|------|------|------|
| `AiTrace`（全链路追踪） | 从未被调用，`hxt_ai_trace` 0 行 | 全项目仅自引用 |
| `AnswerValidator`（答案校验） | 0 引用 | grep 无调用 |
| `UserProfileMemory`（用户画像） | 0 引用 | 表 `hxt_user_ai_profile` 空 |
| `MemorySummarizer` / `ShortTermMemory` / `SummaryMemory` | 0 引用；`SemanticChatMemory` 只读不写 | 摘要永远 `null` |
| `KnowledgeRagAdvisor` | 0 引用 | 编排层用旧 Advisor |
| `DataPermissionFilter` | 0 引用 | 数据权限未生效 |
| `aiStats.js`（前端） | 调的 4 个接口后端都不存在（404） | `/ai-stats/dashboard` 等 |

- **影响**：README 宣称“全链路追踪/用户画像/语义记忆”，实际表是空的；论文写“已实现”会被现场验证打脸。
- **改法**：T12（要么接线，要么从文档和论文里删掉）。

#### P1-9 考试 / 排课只有半套

- 考试：后端 3 个查询接口，无增删改、无页面、无菜单。
- 排课：只有 `CourseScheduleMapper` + `CourseTools`，无 Controller、无页面。
- **影响**：开题报告“课程管理、考试管理”两块讲不完整；“课表查询”只能通过 AI 问，管理员无法维护。

#### P1-10 知识库 / 预警 / 调用日志没有页面

- 知识库只有 `KnowledgeController`，前端无入口。
- 预警无页面。
- 调用日志只有表。
- **影响**：答辩演示只能靠 Swagger/curl，体验分低。

### P2 体验与工程（决定“像不像一个能交付的系统”）

| # | 问题 | 证据 | 建议 |
|---|------|------|------|
| P2-1 | 前端用十几条正则“洗”模型输出（去 `**`、去表格竖线、去 SQL 片段），Markdown 不渲染 | `views/ai/index.vue` 第 200-233 行 | 后端输出规范化 + 前端 `markdown-it` 渲染 + 代码高亮 |
| P2-2 | SSE 无“停止生成/重试/错误事件”；429 返回 JSON，前端仍按 SSE 解析 | `AiChatController`、`RateLimitInterceptor` | `AbortController` + `event: error` + `response.ok` 判断 |
| P2-3 | 缓存是整个 Hash 共用一个 TTL，每次写入都续期；旧条目可能永不过期 | `AiAnswerCache.put` | 一条缓存一个 key（`SETEX`），或按 field 过期 |
| P2-4 | Token 数按“字符数/1.3”估算，统计虚高 | `AiOrchestratorService.asyncPersist` | 用 `ChatResponse` 的 usage 元数据 |
| P2-5 | 限流是全局单例，不是按用户/IP | `RateLimitInterceptor` | 按 userId/IP 维度 + SSE 并发上限 |
| P2-6 | 文档漂移：README 写 `songjiang/123456`（实为 `654321`）、路径写 `/attendances`（实为 `/attendance`）；`CLAUDE.md` 还停留在“13 个 Tool、4 张表” | README、CLAUDE.md | 统一以代码为准重写 |
| P2-7 | 无数据库迁移、无业务表 DDL、无部署脚本/CI | `db/` 只有 `schema-extend.sql`，且 `record_time` 与 DDL 的 `create_time` 不一致 | Flyway + `docker-compose` |
| P2-8 | MyBatis 用 `StdOutImpl` 打 SQL；日志无分级脱敏 | `application.yml` | 改 SLF4J + 生产级别关闭 SQL 打印 |

## 4. 完善方案

### 4.1 路线图（按“能演示 → 能讲圆 → 能答辩”三段）

### 4.2 M1：修阻断（T1–T8）

#### T1 数据库基线化（0.5 人日）

- 用 `mysqldump --no-data huixuetong` 导出 22 张表，落到 `src/main/resources/db/migration/V1__baseline.sql`。
- 引入 Flyway（`spring-boot-starter-flyway` 或 `flyway-core` + `flyway-mysql`），`baseline-on-migrate=true`。
- `V2__fix.sql`：
  ```sql
  -- 1) 审计日志支持 emoji
  ALTER TABLE emp_log MODIFY return_value  TEXT CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;
  ALTER TABLE emp_log MODIFY method_params TEXT CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;
  -- 2) 清理孤儿考勤（21 条）
  DELETE a FROM attendance a LEFT JOIN clazz c ON a.clazz_id=c.id WHERE c.id IS NULL;
  -- 3) 补索引
  CREATE INDEX idx_att_clazz_date ON attendance(clazz_id, attend_date);
  CREATE INDEX idx_score_exam ON score(exam_id);
  CREATE INDEX idx_pay_status_date ON payment(status, payment_date);
  ```
- 修正 `schema-extend.sql`：`hxt_token_usage` 用 `record_time`（与 Mapper 一致），去掉 `CAST(... AS JSON)` 相关注释。
- **验收**：空库执行 `flyway migrate` 后启动成功；`attendance.clazzName` 不再为 null。

#### T2 修复知识库并真正接入 RAG（2 人日）

1. **去 JSON 语法**（`KnowledgeChunkMapper`）：
   ```java
   @Insert("INSERT INTO hxt_knowledge_chunk(doc_id, chunk_index, content, token_count, embedding_json, create_time) " +
           "VALUES(#{docId}, #{chunkIndex}, #{content}, #{tokenCount}, #{embeddingJson}, NOW())")
   ```
   `embedding_json` 保持 `TEXT`，MySQL 5.5/8.0 都能跑；升级 8.0 后再考虑 JSON 列。
2. **解析器**：`.txt/.md` 直读；`.docx` 用 POI、`.pdf` 用 PDFBox（或统一 Tika），替换现在的“按 UTF-8 读字节”。
3. **接线**：`AiOrchestratorService` 把 `QuestionAnswerAdvisor` 换成 `KnowledgeRagAdvisor`；`KNOWLEDGE_RAG` 分支用 `knowledgeBaseService.searchToContext(message, 3)`；`notice type=3` 作为兜底候选（现有逻辑保留在 `KnowledgeBaseService.searchNoticeChunks`）。
4. **检索**：MySQL 5.5 没有 ngram 全文索引，先用“关键词倒排 + 现有 `rerankScore`”；升级 8.0 后建 `FULLTEXT ... WITH PARSER ngram`。
5. **前端**：新增 `/knowledge` 页面（上传、列表、状态、删除、检索预览），菜单挂到“教学管理”。
6. **验收**：上传 3 份制度文档 → 问“缓考流程是什么” → 回答引用文档标题且不再出现 `暂无`。

#### T3 业务闭环（1.5 人日）

- `AttendanceController` 补 `POST/PUT/DELETE`（Mapper 已有 `insert/update/deleteById`），写入前校验 `studentId/clazzId` 存在，成功后 `aiAnswerCache.clear()`。
- `ExamController` 补 CRUD + 前端 `views/exam`，菜单加入“教学管理”。
- 排课二选一：
  - **补齐**：`CourseScheduleController`（按班级/日期查、增删改）+ 课表页；
  - **裁剪**：明确写“排课由教务系统导入，本系统只读”，从 README/论文里降级为“课表查询”。
- **验收**：页面新增一条考勤能落库并在列表出现；考试可增删改查。

#### T4 AI 稳定性与输出规范（1.5 人日）

1. **后端统一清洗**（不要只靠前端）：
   ```java
   // 覆盖 DSML / LongCat / 旧 [[TOOL]] 三种
   text = text.replaceAll("(?s)<｜｜DSML｜｜.*?(</｜｜DSML｜｜[^>]*>|$)", "");
   text = text.replaceAll("(?s)<longcat_tool_call>.*?</longcat_tool_call>", "");
   text = text.replaceAll("(?s)\\[\\[TOOL\\]\\].*?\\[\\[END_TOOL\\]\\]", "");
   ```
   放在 `AiOrchestratorService` 的 `streamAnswer` / 工具分支返回前；前端正则只做兜底。
2. **注入当前日期**：`AiPromptBuilder.build` 追加
   ```java
   sb.append("\n\n【当前日期】").append(LocalDate.now())
     .append("（").append(dayOfWeek).append("）");
   ```
   工具描述里也写明“日期缺省=今天，返回中必须带实际日期”。
3. **默认模型**：`ChatClientConfig` 的默认值改为 `modelRegistryService.list().get(0).getType()`；删掉 `ScheduledAgentService`/`MemorySummarizer` 里的 `"longcat"` 硬编码。
4. **请求级降级**：`stream()` 外层捕获异常后换备用模型重试一次，仍失败再返回兜底文案。
5. **前端**：`result.code === 1`；SSE 加 `AbortController`“停止生成”；错误用 `event: error`。
6. **验收**：同一组 10 个问题在 deepseek/mimo 下都不出现工具标记；问“今天”返回真实日期。

#### T5 账号与密码（1 人日）

- 引入 `spring-security-crypto`（只做 BCrypt，不引入整套 Security）。
- 登录：`passwordEncoder.matches(raw, db)`；兼容旧明文——首次登录成功后自动 `upgradeEncoding` 写回 BCrypt。
- `emp` 增加 `role`（`ADMIN/TEACHER/STUDENT`）或独立 `sys_role`；`student` 增加 `username/password`（或独立 `student_account`）。
- 管理员重置密码：`PUT /emps/{id}/password/reset`（生成随机 8 位，返回一次）。
- 登录失败 5 次锁定 10 分钟（Redis 计数）；登录页加图形验证码。
- **验收**：库里看不到明文；学生账号可登录且只进学生端。

#### T6 权限真正生效（1 人日）

- **验收**：学生 token 调 `/emps` 返回 403；教师改不了 `/ai/models`；匿名访问 `/actuator/env` 返回 401。

#### T7 分页下沉（1 人日）

- `Score/Payment/Notice/Violation/Employment` 五个 `page` 改为 SQL `LIMIT #{offset},#{pageSize}` + `COUNT(*)`，与已改造的 `AttendanceMapper.findPage` 保持一致。

- **验收**：造 1 万行成绩，分页 P95 < 300ms；总数与列表一致。

#### T8 审计与字符集（0.5 人日）

### 4.3 M2：补齐开题报告的“承诺项”（T9–T13）

#### T9 学业预警（论文核心创新点，3 人日）

**数据表**
```sql
CREATE TABLE hxt_warning (
  id BIGINT AUTO_INCREMENT PRIMARY KEY,
  student_id INT NOT NULL,
  clazz_id INT,
  warn_type VARCHAR(20) NOT NULL,   -- SCORE / ATTENDANCE / PAYMENT / VIOLATION
  warn_level TINYINT NOT NULL,      -- 1提示 2预警 3严重
  reason VARCHAR(500) NOT NULL,
  metric_json VARCHAR(1000),
  status TINYINT DEFAULT 0,         -- 0未处理 1已处理 2已忽略
  handler_id INT, handle_time DATETIME,
  create_time TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  UNIQUE KEY uk_student_type_day (student_id, warn_type, create_time)
);
```

**规则（全部用现有表就能算）**
| 类型 | 规则 | 数据源 |
|------|------|--------|
| 成绩 | 不及格 ≥ 2 门，或平均分 < 60 | `score` + `exam.pass_score` |
| 考勤 | 近 30 天出勤率 < 80%，或连续旷课 ≥ 3 天 | `attendance` |
| 缴费 | 待确认/未缴 > 30 天 | `payment` |
| 违纪 | 累计扣分 ≥ 10 | `violation_log` |

**实现**
- `WarningService.scan()`：`@Scheduled(cron = "0 0 2 * * ?")` 每日 02:00 扫描；同学生同类型当天幂等。
- `WarningController`：列表（按班级/类型/等级/状态）、详情、处理（标记已处理/忽略）。
- 推送：新增 `hxt_message`（站内信）或复用 `notice` + `target_audience='STUDENT'`；学生端/教师端红点。
- 可选加分：规则命中后调 LLM 生成“预警说明 + 改进建议”，Prompt 只喂规则数据，避免幻觉。
- **验收**：造 3 条异常数据 → 次日生成 3 条预警 → 学生端可见、教师端可处理。

#### T10 三角色前端（2.5 人日）

- 路由加 `meta.roles`，`router.beforeEach` 校验 `loginUser.role`；菜单按角色动态渲染。
- 学生端页面（复用现有接口 + 数据权限）：
  - 我的课程（`/courses` + 班级）
  - 我的成绩（`/scores/student/{id}`）
  - 我的缴费（`/payments/student/{id}`）
  - 公告（`/notices`，按 `target_audience` 过滤）
  - 学业预警（T9）
  - AI 问答（复用 `/ai/chat`，Prompt 注入“学生视角”）
- 教师端：只保留自己班级的考勤/成绩/预警。
- 管理员端：现有全部 + 账号管理 + 模型 + 监控 + 日志。
- **验收**：三个账号登录后菜单、可访问接口、可查数据范围都不同。

#### T11 RAG 升级为“混合检索”（2 人日，可与 T2 合并）

- Embedding：接一个 OpenAI 兼容的 embedding 接口（如 `text-embedding-v3` / `bge-m3`），在 `models.json` 增加 `embedding` 类型；上传时写入 `embedding_json`（float 数组）。
- 检索：关键词得分（现有 `rerankScore`）+ 向量余弦相似度 → **RRF 融合**：
  `score = 1/(60+rank_kw) + 1/(60+rank_vec)`，取 Top3。
- 返回引用：`docId / fileName / chunkIndex / score`，前端回答下方展示“来源”。
- **验收**：30 条制度问答评测集，Recall@3 ≥ 85%，回答带来源。

#### T12 可观测性（2 人日）

- **接线 `AiTrace`**：Controller 进入 `start()`，流结束/异常 `end()`；`toolCalls` 通过 `@Tool` 包装或 AOP 累加。
- **`hxt_tool_call_log`**：在 Tool 调用处记录 `tool_name / args / success / duration_ms`。
- **页面**：
  - `/ai-logs`：trace 列表（时间/用户/意图/模型/耗时/状态/工具数），详情抽屉展示工具链与错误。
  - `/monitor`：模型健康（复用 `AiHealthIndicator`）、P95 延迟、错误率、限流命中、Token 成本。
- Actuator：`show-details: when_authorized`；健康检查恢复 AI 组件（当前被 `management.health.ai.enabled=false` 关掉）。
- **验收**：每次对话都能在页面查到一条 trace + N 条工具日志；deepseek 挂了监控页变红。

#### T13 测试与压测（2 人日）

- 修 2 个失败用例（`DeptControllerTest` 期望 400；`SecureSqlExecutorTest` 与当前安全策略对齐）。
- 补 MockMvc 集成测试：登录、AI 同步、知识库上传、越权访问、分页边界。
- Apifox 自动化：现有 `apifox/openapi.json` + `01-login-extract-token.js` + `02-common-assertions.js`，补 CI 命令。
- JMeter：普通接口 100 并发、SSE 50 并发，产出 TPS/P95/错误率报告。
- AI 质量评测集：30 问（统计/查询/RAG/多轮/越权/注入），指标：工具命中率、答案准确率、幻觉率、平均时延。
- **验收**：`mvn test` 全绿；压测报告与评测表可直接进论文第 5 章。
